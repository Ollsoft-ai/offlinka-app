# Offlinka for Android

Kotlin + Jetpack Compose app that reads the Offlinka drive through the Storage Access Framework and the Rust core (`../core`, UniFFI bindings). Product and contract: `../docs/SPEC.md`. Device checklist: `../docs/DEVICE-TESTS.md`.

## Modules

- **`:app`** (`cz.offlinka.app`): drive access (`drive/`: SAF scan, maxi-over-mini choice, unplug watch, index copies), the WebView reader (`reader/`: `https://offlinka.local/<bookId>/<path>` served from the core, Range, 404, everything else blocked), Room (saved, history, recent searches), settings, view models, navigation.
- **`:ui`** (`cz.offlinka.ui`): theme, components and every screen as stateless composables. Theme, strings (cs default, sk, en), fonts and icons come **generated from `../design/out/android`** at build time (never copy them by hand). Paparazzi screenshot tests live here.
- **`:core`** (`cz.offlinka.core`): UniFFI Kotlin bindings, generated by `../scripts/gen-bindings.sh` into `core/src/main/kotlin`. The module compiles a copy without the generated (unused) `import com.sun.jna.Library`, which would shadow the core's own `Library` class.
- **Native libs are build output, not in git:** run `../scripts/build-android-core.sh` before `assemble*`/`bundle*` (fills `app/src/main/jniLibs/{arm64-v8a,armeabi-v7a,x86_64}`). Without them the APK installs but cannot open books.

## Build (on Company OS)

Every Gradle run under the shared lock, no daemon:

```
source ~/opt/offlinka-env.sh
cd android
flock /tmp/claude-1000/offlinka-app-build.lock nice -n 10 timeout 3600 ./gradlew --no-daemon assembleDebug
```

- Gradle runs on **JDK 21** (Paparazzi and Robolectric for API 35 need it): `gradle/gradle-daemon-jvm.properties` downloads it on first use when only JDK 17 is installed.
- Tasks: `assembleDebug`, `assembleRelease` (R8 + resource shrink, universal APK), `bundleRelease` (AAB for Play), `test` (all JVM tests), `lint`.
- Screenshots: `:ui:verifyPaparazziDebug` checks against the goldens, `:ui:recordPaparazziDebug` rewrites them. Goldens: `ui/src/test/snapshots/images/` (cs/en × light/dark of every screen).
- Host-core tests (`:core:testDebugUnitTest`, `CoreIntegrationTest` in `:app`) load `../core/target/host/linux-x86-64/libofflinka_core.so` (build it with `../scripts/gen-bindings.sh` or `../scripts/build-host-core.sh`) and read the ZIMs in `/srv/offlinka/drive/release/2026-11.3/files` (`OFFLINKA_DRIVE_FILES` to override). They skip themselves when either is missing.

## Instrumented tests (emulator)

`src/androidTest`: the real app (real core, real WebView) with a folder as the drive. `FixtureRunner` starts `FixtureApp`, whose `FolderDrive` (test-only `DriveAccess`) serves `filesDir/fixture-drive/Knihovna/offlinka_cs_prirucky.zim` (copied from the APK's assets); the system folder picker is answered with Espresso-Intents. `DriveFlowTest`: Connect → Home, search „prvni pomoc“ → article → "Zpět" back to the search, pulling the folder mid-read → unplugged cover → putting it back → the article. Run with `./gradlew connectedDebugAndroidTest` on a device or emulator (CI does it on API 26/30/36; this box has no KVM).

## Release signing

Only from env vars, never from a file in the tree: `OFFLINKA_KEYSTORE`, `OFFLINKA_KEYSTORE_PASSWORD`, `OFFLINKA_KEY_ALIAS`, `OFFLINKA_KEY_PASSWORD`. **The APK (drive) and the AAB (Play) are both signed with the app signing key** (`OFFLINKA_SIGNING_*`): Play holds the same key and registered no separate upload key (store/RELEASE.md, 2026-11-25). An AAB signed with `OFFLINKA_UPLOAD_*` is rejected by Play. A release build (APK or AAB) without them fails in `checkReleaseSigning`; it never falls back to the debug key. Debug builds, unit tests and lint need nothing. CI only: with `CI=true` (GitHub Actions) or `-Pofflinka.unsignedRelease=true` the release builds **unsigned** (to check R8 and shrinking; not installable). Read the key password in the shell, never print it.

## Decisions worth knowing

- **No INTERNET permission.** WebView loads only what `ContentServer` answers; any other host gets an empty 403.
- **Never writes to the drive.** Read-only SAF descriptors (ZIMs and `.offidx` indexes are handed to the core as detached fds; the core reads with `pread`, no `mmap`, so a pulled drive is an `Io` error, never SIGBUS). The only copy the app makes is a PDF opened from the guides (app cache).
- **compileSdk/targetSdk 36** (Google Play requirement since 2026-08-31, SPEC updated); AndroidX versions are the newest whose AAR metadata still allows compileSdk 36 (`gradle/libs.versions.toml`).
- **Guides: always the app's own edition.** The drive's `offlinka_cs_prirucky.zim` still explains the Kiwix apps (founders' rule until the store launch), so the shelf leaves it out everywhere (Home, Library, search) and serves the copy bundled in the APK (`scripts/build-app-guides.py`); the drive's book count still includes the file. The bundled guides get an on-device index like drive books.
- **Picked folder one level too high** (the review sample unzipped into Download): when the picked folder's only relevant child is `OFFLINKA`, the shelf reads that folder (two levels at most).
- **Crash guards:** a dead WebView renderer (`onRenderProcessGone`) is replaced by a new WebView on the same page; a missing or updating system WebView shows a retry; database writes on a full disk are logged and dropped (`safeWrite`); files handed to other apps are copied in 1 MB chunks and refused over 50 MB.
- **WebView privacy:** `MetricsOptOut` on and Safe Browsing off in the manifest (all pages are local); release builds strip `Log.v/d/i`, and no log line carries an article URL.
- **Licences:** `assets/reader/licences.html` holds the full texts (regenerate with `scripts/gen-licences.py` after a core dependency change); About → Open-source libraries → Úplná znění licencí opens it in the reader.
- **Index builds keep the screen on, no foreground service** (decided round 3: a dataSync service needs a Play Console declaration and review). While any index is built and the app is visible, `FLAG_KEEP_SCREEN_ON`; the note says "Nechte aplikaci otevřenou". A killed build starts that book over. The index folder is cleaned on every load: only indexes of books in a remembered drive's last listing stay, `*.part` goes, a phone-built index goes when the drive ships its own `.offidx`. An `Io` error with the drive still there skips that book only; "Ve frontě" / "Málo místa" show in book details, "Zastavit přípravu" there too (it forgets the English request).
- **Retired books** are closed (`closeFile`) on the IO dispatcher, never on the main thread: a read hanging on a pulled drive would hold the close.
- **One origin, no service workers:** every page gets a script that unregisters service workers, and service-worker fetches are refused (403). Dialer/mail links and file downloads need a user gesture.
- **Search inside the guides:** h2/h3 headings of the guides book are indexed in memory (GuideSections), so "krvaceni" finds "První pomoc › Silné krvácení"; the guides group leads when it matches.
- **Search indexes on the phone:** drives without `.offidx` get them built in `noBackupFilesDir/indexes` (core `build_index`, file name = ZIM name + size, so a new edition rebuilds and the old one's index is deleted), UI-language Wikipedia first, every book except English top1m; that one only from its details (warning, phones with 3 GB+ RAM, request kept across restarts). Progress on Home and in Search, cancellable, never blocks reading. Index tables preload when Search opens.
- **Retired books** (unplug, rescan) get `closeFile()` only, after the new state is published; the UniFFI cleaner frees them once unreferenced. A WebView read on a retired book gets Io → 503 → the reader reloads. Books opened but never published are destroyed at once.
- **Memory:** one 48 MB cluster cache for all books (32 MB on low-RAM phones); `onTrimMemory` → core `trimMemory()`.
- **Startup:** the UI-language Wikipedia opens first and Home shows at once; the other books open in parallel (3 at a time) and fill in.
- **Bundled guides:** `app/src/main/assets/offlinka_cs_prirucky.zim` (from the drive release) is copied to app storage on first start, so První pomoc works with the drive unplugged.
- **Maps:** map pages get `assets/reader/map-bridge.js`, which routes MapLibre worker fetches through the page (always intercepted). Check in Chromium: `PLAYWRIGHT_BROWSERS_PATH=/srv/offlinka/tools/ms-playwright atd-render timeout 120 node android/tools/map-bridge-check/run.cjs`.
- One `WebView` per activity (`ReaderController`), so the reading history survives moving between screens; a search started in the reader returns its result into the same history.
