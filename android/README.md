# Offlinka for Android

Kotlin + Jetpack Compose app that reads the Offlinka drive through the Storage Access Framework and the Rust core (`../core`, UniFFI bindings). Product and contract: `../docs/SPEC.md`. Device checklist: `../docs/DEVICE-TESTS.md`.

## Modules

- **`:app`** (`cz.offlinka.app`): drive access (`drive/`: SAF scan, maxi-over-mini choice, unplug watch, index copies), the WebView reader (`reader/`: `https://offlinka.local/<bookId>/<path>` served from the core, Range, 404, everything else blocked), Room (saved, history, recent searches), settings, view models, navigation.
- **`:ui`** (`cz.offlinka.ui`): theme, components and every screen as stateless composables. Theme, strings (cs default, sk, en), fonts and icons come **generated from `../design/out/android`** at build time (never copy them by hand). Paparazzi screenshot tests live here.
- **`:core`** (`cz.offlinka.core`): UniFFI Kotlin bindings, generated by `../scripts/gen-bindings.sh` into `core/src/main/kotlin`. The module compiles a copy without the generated (unused) `import com.sun.jna.Library`, which would shadow the core's own `Library` class.
- **Native libs are build output, not in git:** run `../scripts/build-android-core.sh` before `assemble*`/`bundle*` (fills `app/src/main/jniLibs/{arm64-v8a,armeabi-v7a,x86_64}`). Without them the APK installs but cannot open books.

## Build (on Company OS)

Every Gradle run under the shared lock, no daemon:

```
source ~/opt/offlinka-env.sh
cd android
flock /tmp/claude-1000/offlinka-app-build.lock nice -n 10 timeout 3600 ./gradlew --no-daemon assembleDebug
```

- Gradle runs on **JDK 21** (Paparazzi and Robolectric for API 35 need it): `gradle/gradle-daemon-jvm.properties` downloads it on first use when only JDK 17 is installed.
- Tasks: `assembleDebug`, `assembleRelease` (R8 + resource shrink, universal APK), `bundleRelease` (AAB for Play), `test` (all JVM tests), `lint`.
- Screenshots: `:ui:verifyPaparazziDebug` checks against the goldens, `:ui:recordPaparazziDebug` rewrites them. Goldens: `ui/src/test/snapshots/images/` (cs/en × light/dark of every screen).
- Host-core tests (`:core:testDebugUnitTest`, `CoreIntegrationTest` in `:app`) load `../core/target/host/linux-x86-64/libofflinka_core.so` (build it with `../scripts/gen-bindings.sh` or `../scripts/build-host-core.sh`) and read the ZIMs in `/srv/offlinka/drive/release/2026-11.3/files` (`OFFLINKA_DRIVE_FILES` to override). They skip themselves when either is missing.

## Release signing

Never in git. Either env vars `OFFLINKA_KEYSTORE`, `OFFLINKA_KEYSTORE_PASSWORD`, `OFFLINKA_KEY_ALIAS`, `OFFLINKA_KEY_PASSWORD`, or a properties file (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`) at `$OFFLINKA_KEYSTORE_PROPERTIES` or `android/keystore.properties` (git-ignored). Without either, release is signed with the debug key and the build says so.

## Decisions worth knowing

- **No INTERNET permission.** WebView loads only what `ContentServer` answers; any other host gets an empty 403.
- **Never writes to the drive.** Read-only SAF descriptors (ZIMs and `.offidx` indexes are handed to the core as detached fds; the core reads with `pread`, no `mmap`, so a pulled drive is an `Io` error, never SIGBUS). The only copy the app makes is a PDF opened from the guides (app cache).
- **compileSdk/targetSdk 35** per SPEC; AndroidX versions are the newest whose AAR metadata still allows compileSdk 35 (`gradle/libs.versions.toml`).
- One `WebView` per activity (`ReaderController`), so the reading history survives moving between screens; a search started in the reader returns its result into the same history.
